# Model Routing

The Gauntlet routes by capability, not by uniqueness. A strong model may intentionally be reused for several roles.

Recommended role classes:

- Orchestrator / implementation: strongest available agentic coding/reasoning model.
- Architect: same strong model when repository-scale reasoning matters.
- Design strategist: strong reasoning or multimodal model.
- Image judge: model with native image input.
- Video/player judge: model with native video input when available.
- Systems/evidence referee: strongest independent reasoning model available.
- Performance audit: fast model that can inspect measurements and code efficiently.
- Blind-spot check: independent secondary model; never gate authority.
- Asset/3D specialist: strong tool-using multimodal model when 3D tooling exists.

For the free OpenCode roster used by the original project, the default mapping was:

- Muse Spark 1.3 Free — orchestrator, builder, architecture, visual image, release, asset specialist.
- MiMo V2.5 Free — design, player, video, experience review.
- Nemotron 3 Ultra Free — systems and evidence referee.
- Nemotron 3.5 Lightning Free — performance/fast audit.
- Big Pickle Free — blind-spot secondary opinion.
- Ling 3.0 Flash Fin Free — optional auxiliary critic only.
- Muse Spark 1.2 Free — fallback when needed.

Model benchmarks and availability change over time. Verify current provider/model IDs before publishing a new routing update; do not present an old benchmark number as current fact.
